## 1. Verdict

**Doable.** The data path is proven end to end: Open Beauty Facts dump →
16,635 labels → 99.4 % parsed by the MIT `on-the-list` parser; CosIng annexes
are five free CSVs with a working official export endpoint; the missing
inventory/function layer is available from a free, CC BY 4.0 mirror. The code
that remains is glue, not research.

**But not at the current scope.** The plan's job queue, multi-agent locks,
remote MCP, OCR and SQLite export are v2. The v1 product is a local,
single-process, deterministic tool over a small private data directory.

Three findings change the plan:

1. **OBF is up.** The 502s in the research were an outage, not a block. The
   gzipped CSV dump is 17.9 MB and 64,237 rows; the API works for a real
   barcode. Use the dump for bulk, the API only for a single user scan.
2. **CosIng annex content is stable; the raw bytes are not.** Live CSVs differ
   from the 2026-09-09 pinned package only in the two export-metadata lines
   (`File creation date`, `Last update`). Strip those before hashing, or every
   build will see a false registry change.
3. **The inventory/functions gap is closable for free.** CosIng Checker exposes
   28,712 ingredients, 30,418 glossary entries and 83 functions, CC BY 4.0, no
   key, 120 requests/min. Its annex snapshot is stale, so use it only for
   names/functions and the live CosIng CSVs for annexes.

### Correction that matters most

The raw annex CSV hashes change even when the annex content does not:

```
live Annex II  sha256 5999e783…
pkg  Annex II  sha256 b7105a05…
after dropping the two metadata lines: byte-for-byte identical
```

The same is true for all five annexes. `File creation date` is the export
timestamp; `Last update` is the Commission's update field. **Pin the stripped
content hash plus `last_update`; keep the raw file for audit.** Otherwise every
on-demand run commits a new registry and every report cites a different
`sha256` for identical data.

## 3. Is it doable?

Yes, with the following evidence:

- **Bulk product data is free and complete enough.** 64,237 products; 16,635
  usable panels. The parser gets 99.4 % of them. The remaining 0.6 % is the
  prose/heading tail the research already budgeted for.
- **Regulatory data is free and citable.** Five annex CSVs, 1,758 + 381 + 154 +
  58 + 34 rows, with reference numbers, CAS/EC, maximum concentrations,
  warnings and the `Identified INGREDIENTS` column. Annex matches are string
  matches with a citation, not verdicts.
- **Canonical names and functions are free.** The CosIng Checker mirror covers
  28,712 ingredients and the EU 2025/1175 glossary (30,418 rows), plus 83
  functions. It is a third-party mirror, so values are stored with
  `source: cosingchecker`, `method: mirror`, `confidence` and a snapshot date.
- **The query path needs no network.** `lookup`, `parse`, `analyze`, `resolve`,
  `shelf`, `export` and `doctor` can run from `data/` with `--offline`.
- **CI is free.** A public repo with `workflow_dispatch` only uses standard
  GitHub-hosted runners for free. There is no nightly quota burn; each run is
  paid for by the invocation, not by the clock. No paid runner, no card.

### Risks and mitigations

| Risk | Mitigation |
|---|---|
| OBF outage or dump removal | Keep the last good `data/` commit; `doctor` reports freshness; never make a query depend on OBF being up. |
| CosIng Checker disappears or drifts | Treat it as a bootstrap: snapshot the fields used, store source/version, and keep the annex path on the official CSVs. |
| `no SaaS` read strictly | The mirror is free and keyless, but it is third-party SaaS. Core v1 does not need it: OBF + official annexes still work. If the constraint is strict, cut functions/glossary or scrape the official CosIng inventory; do not make the tool depend on the mirror. |
| Raw registry hash churn | Content hash over normalized rows; metadata stored separately. |
| Scraping fragility / robots changes | Runtime check per run; budget 1 req / 2 s, 50 pages; stop host on 403/429/challenge; work orders instead of retries. |
| OCR tail | Cut from v1. Barcode + pasted text first; OCR is a separate spike. |
| ODbL share-alike | The repo is public, so `data/` is ODbL: attribute OBF, keep the database ODbL, and keep scraped panels in gitignored `local/`. |
| Go parser port diverges from the validated Python parser | Port the MIT parser, then gate it against the 16,635-label corpus: target 16,535 parsed and 298,423 tokens. Keep the Python package as an offline oracle only. |

## 4. v1 scope

### Keep

- `lookup <barcode>` from the local OBF-derived index; API fallback for a
  single unknown barcode.
- `parse` from `--text`, `--file`, stdin; ordered list, `may_contain[]`,
  unresolved tokens verbatim.
- `analyze`: canonical name, functions (if mirrored), annex citation
  (annex + reference number), `declared_pct: null` unless printed.
- `resolve`: deterministic chain only; `method` + `confidence` per row.
- `shelf add/ls/rm`; `shelf report` rollup (duplicates, function groups,
  annex matches — no safety/efficacy verdict).
- `export --format json|csv`.
- `doctor`: registry content hash, `last_update`, data freshness, cache size,
  host budgets, OBF/CosIng health.
- JSON envelope, exit codes, `work_orders`, `--offline`, provenance on every
  stored value.
- Atomic writes (`tmp` + rename) and idempotence: unchanged content must not
  rewrite files or change `fetched_at`.

### Extend

- **CosIng Checker as the inventory/glossary bootstrap (optional).** Use
  `/api/v1/inci-glossary/`, `/api/v1/ingredients/` and `/api/v1/functions/`;
  snapshot once, store the source version (`EU 2025/1175`) and `fetched_at`.
  Never use its annex tables; use the live CosIng CSVs. If `no SaaS` is strict,
  cut this layer or replace it with an official CosIng scrape.
- **Content-hash registry.** `manifest.json` records stripped CSV sha256,
  `last_update`, source URL, `fetched_at`. Reports cite the content hash and
  the Commission's date.
- **`may_contain` split** from the label parser; colourants in that block are
  not order-comparable.
- **Source consensus.** One observation = `unverified`; two independent hosts
  ≥ 90 % identical = `verified`; conflicts kept, not resolved silently.
- **`diff` command.** Previous observation vs new label; previous registry vs
  new registry. Useful for the agent and for CI summaries.
- **Granular warnings.** `obf_api_fallback`, `cosingchecker_snapshot`,
  `registry_metadata_only_change`, `label_prose_detected`.
- **Optional later:** OCR, local LLM span extraction, remote read-only MCP.
  Each stays behind a flag and records its method.

### Cut from v1

- Job files, `state/jobs`, `state/locks`, `queue/`, claim files, multi-agent
  coordination. One process; atomic writes are enough.
- Remote MCP / public HTTPS endpoint / ChatGPT connector. It needs a public
  host, a paid ChatGPT plan for full MCP, and publishes private shelf data.
  Local stdio MCP is enough for an agent on this machine.
- `export --format sqlite`. JSON files are the source of truth; add SQLite only
  when the shelf is large enough to need it.
- OCR and local-LLM resolution. Barcode + pasted text first.
- Batch `ingest` jobs and `job get/ls`. Sequential URLs in one process.
- Full-corpus scraping. Only products on the shelf or explicitly requested.
- Search ranking, fuzzy matching, "actives" editorial layer, concentration
  inference, safety/efficacy verdicts.
- Actions as a query API (204 / PAT / cold start). The query path is local.

## 5. Where the inventory lives

The repo is public. Keep open data in `data/` and the personal/scraped overlay
in gitignored `local/`.

```
data/
  products/<product_key>.json         # OBF/CosIng-derived, public
  ingredients/<slug>.json
  registry/cosing/annex_II..VI.csv + manifest.json
  index/products.json
  index/ingredients.json
  shelf/<name>.json                   # only if you choose to publish it
local/                                # gitignored
  shelf/<name>.json                   # default private shelf
  sources/<sha256>.json               # scraped observations
  cache/http/...
```

- `data/` is ODbL (OBF-derived) / CC BY 4.0 (CosIng-derived); see
  [`DATA-LICENSE.md`](../DATA-LICENSE.md).
- `local/` is never committed. Scraped panels and the shelf live there by
  default. If you want the shelf public, move it to `data/shelf/`; ChatGPT can
  then read it without a token.
- Commit only the small generated JSON. Never commit the 17.9 MB gzip CSV, the
  104 MB gzip JSONL, raw HTML, images, cookies or the HTTP cache.
- One JSON file per product keeps diffs reviewable and Git history useful; no
  binary SQLite in Git, no LFS.
- `generated: true` + `generator_version` on every generated file. Do not put a
  wall-clock `generated_at` in files that did not change; that breaks
  idempotence and produces a diff on every run.
- Public ODbL share-alike is active: attribute Open Beauty Facts and keep the
  database ODbL. Scraped data is excluded from the public repo.

## 6. Free CI/CD

Recommended: **public GitHub repo**, `workflow_dispatch` only, no schedule, no
push/PR trigger.

| Piece | Free choice | Why |
|---|---|---|
| Runner | `ubuntu-latest`, standard GitHub-hosted | Standard runners are free and unlimited on public repos. |
| Trigger | `workflow_dispatch` | Manual UI, `gh workflow run`, or a ChatGPT Action/MCP. No cron, no auto-run. |
| Registry | Download five CSVs, strip metadata, hash rows, update manifest only on content change | Avoids false diffs. |
| OBF | Download CSV, extract requested barcodes, update only changed products | Bulk via dump; API only for a single scan. |
| Result | The run commits `ci/last-run.json` | Status, conclusion, commit, run URL and error tail are machine-readable. |
| Tests | Go tests + parser fixture (when code exists) | No PR trigger; run them on demand too. |
| Storage | Commit `data/`, cache Go modules/build | No artifact-as-storage. |
| Query | Local CLI / stdio MCP | Actions cannot serve chat turns; no PAT, no cold start. |
| Pages | Optional read-only later | Free on public repos; not needed for v1. |
| Remote MCP | Deferred | Needs a public host and a ChatGPT plan for full MCP; the token belongs in a narrow Action/proxy. |

There is no 60-day auto-disable problem because there is no schedule. Each run
is one explicit invocation; standard public-repo Actions minutes are free. The
workflow commits `ci/last-run.json` with `GITHUB_TOKEN` (`contents: write`);
pushes made with that token do not trigger another workflow.

How to start a run and have ChatGPT read the result:
[`run-ci.md`](run-ci.md).

## 7. Language

Measured on this machine (Windows 10, Go 1.25.5 → toolchain 1.26.0, Rust 1.98.1):

| Candidate | Build / CI | Artifact | Runtime | Parser | Verdict |
|---|---|---|---|---|---|
| **Go** | 5.7 s hello (Windows), 12.9 s Linux cross cold; 39.9 s cold with MCP + `x/text` + `x/net/html` incl. toolchain download; warm cache seconds `[INFERENCE]` | **8,085,666 B** Linux static with those deps | ~ms | port (~550 lines core) | **Recommended** |
| Python 3.13/3.14 + uv | no compile; `uv sync` cached; 11.95 s full corpus parse | source/venv; PyInstaller 20–40 MB `[UNVERIFIED]` | ~50–150 ms `[INFERENCE]` | direct import | Fallback if the port is too risky |
| Rust | 12.6 s release hello; real HTTP/HTML deps minutes `[INFERENCE]` | smallest (~5–10 MB with deps) `[INFERENCE]` | fastest | port | Only if absolute size wins |
| TypeScript/Bun | fast bundle; Bun not installed here | ~50–100 MB compiled `[UNVERIFIED]` | fast | port | If a web UI is the priority |
| C#/.NET AOT | moderate | ~10–20 MB `[UNVERIFIED]` | fast | port | No advantage here |

**Decision: Go 1.26, one static binary, no cgo.** It is the best balance of CI
speed, artifact size, startup, cross-compilation and official MCP support
(`github.com/modelcontextprotocol/go-sdk` v1.8.0, MCP spec 2026-07-28). The
cost is the parser port; it is contained by the 99.4 % corpus gate.

If the parser port is rejected, the fallback is Python 3.13 + `uv`: no build,
direct reuse of the validated MIT parser, but no slim binary. Do not run a
Python subprocess from a Go binary; that defeats the point.
